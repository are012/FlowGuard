## N. 신규 발견 (최근 검증에서 확인)

### N1. 중복 분석 실행이 막히지 않음 — **해결**

- **문제였던 것**: 멱등성이 `analysisId` 단위로만 걸려 있어 요청마다 새 ID가 발급됐고, 버튼 연타 시 분석과 유료 AI 호출이 그만큼 반복됨
- **해결**: `(user_id, current_state_revision, trigger_type, as_of)`를 키로 실행 중인 분석을 공유. 같은 조건의 동시 요청은 새로 실행하지 않고 진행 중인 결과를 기다려 함께 받음
- **관련**: `apps/api/flowguard/services/analysis.py` `_AnalysisInFlight`

### N2. `demo/reset`에 환경 가드가 없음

- **근거**: `router.py`의 `@api.post("/demo/reset")`이 `confirmation: Literal["RESET_DEMO"]` 스키마 검증만 하고 환경 조건 없이 동작
- **문제**: 데모 편의 기능이 운영 API와 동일한 조건으로 노출됨
- **조치**: `FLOWGUARD_ENABLE_DEMO_ENDPOINTS` 환경변수 가드를 추가하고 비활성 시 404
- **규모**: 30분

### N3. 위험일이 상세 차트 범위 밖이라 화면에 안 보임 — **해결**

- **문제였던 것**: `safety_margin` 음수일은 기준일로부터 32~33일째인데 상세 차트는 0~27일만 렌더링해, 화면에서는 0원 기준선만 보임
- **해결**: 13주 전체를 주차별로 보여주는 개요 차트를 추가하고 첫 위험 시점에 마커를 표시. 상세 구간은 1~4주를 유지하되 개요에서 위험 시점으로 유도
- **관련**: `apps/web/src/app/cashflow/page.tsx`

### N4. `requires_reanalysis: true` 경로에 테스트가 없음 — **해결**

- **문제였던 것**: 구버전 리포트를 만났을 때 폴백하고 "다시 분석 필요"를 표시하는 경로가 미검증. 잘못된 안전여유를 보여주지 않기 위한 안전장치인데 동작 확인이 안 됨
- **해결**: 재분석 필요 경로를 다루는 테스트가 5개 파일에 존재
- **관련**: `apps/api/flowguard/services/reports.py` `_margin_contract`

### N5. AI 프롬프트에 용어집과 날짜 형식 규칙이 없음

- **근거**: 실제 AI 응답 — `2026-08-25 결제 계정에 250,000원이 부족할 예정입니다. 현재 안전 지출 가능 금액은 350,000원…`
- **문제**: 세 가지가 어긋남
  - 날짜를 ISO 형식(`2026-08-25`)으로 노출. 화면 다른 곳은 `8월 25일 (화)`
  - `결제 계정`(표준: 결제**계좌**), `안전 지출 가능 금액`(표준: 오늘 안심하고 쓸 수 있는 돈)
  - 결정론적 문구와 어투가 충돌 (`32일 뒤 필요한 자금을 준비하세요` vs AI 문장)
- **조치**: `INTERPRETATION_INSTRUCTIONS`에 README 4장 용어 변환표와 날짜 표기 규칙 추가. 변경 시 `promptVersion`을 `3` → `4`로 올릴 것(멱등키에 포함됨)
- **규모**: 30분, 코드 변경 없이 프롬프트만
- **관련**: `apps/api/flowguard/ai_service.py:29`

### N6. 마이그레이션 누락 시 오류 메시지가 불친절함

- **근거**: `alembic upgrade head` 없이 uvicorn을 직접 실행하면 `sqlalchemy.exc.OperationalError: no such table: current_records`
- **문제**: `make dev-api`가 마이그레이션을 선행하므로 정상 절차로는 문제없으나, 저장소를 처음 받은 사람이 uvicorn을 직접 띄우면 원인을 알기 어려운 오류를 만남
- **조치**: 기동 시 스키마 부재를 감지해 "먼저 `make migrate`를 실행하세요" 안내 후 종료
- **규모**: 1시간

## S. 전략

### S1. AI가 수행하는 역할이 지나치게 작음 — **해결**

- **문제였던 것**: 결정론적 코어가 위험 탐지·현금흐름·Safe-to-Spend·위험 가설·도구 선택·대응안 생성·검증·최종 선택을 전부 수행하고, AI는 검증 완료된 후보의 순위화와 설명 문장 생성만 담당했음
- **배경**: `luna.py`(675줄, 도구 선택형 에이전트)를 삭제하면서 AI가 해도 **안전한** 영역까지 함께 제거됨
- **판단 기준**: 안전 원칙은 유지하되 선을 다시 그음

  | AI가 하면 위험 | AI가 해도 안전 |
  |---|---|
  | 금액·날짜 계산 | 무엇을 의심할지 판단 |
  | 위험 등급 판정 | 어떤 근거를 조회할지 선택 |
  | 대응안 효과 수치화 | 어떤 조합을 시도할지 제안 |
  | 정책 통과 여부 결정 | 결과를 사용자 맥락으로 설명 |

- **해결 — 두 갈래로 확장**

  | 트랙 | 내용 | 상태 |
  |---|---|---|
  | A. 라벨 통합 | 거래 문자열만 보고 같은 거래처를 묶어 제안. 금액·날짜 미전달 | 구현 완료 |
  | B. 위험 조사 | AI가 조사 계획을 요청 → 백엔드가 검증 후 도구 실행 → 관찰 결과 전달 → AI가 결론 또는 추가 요청 (2단계 고정) | 구현 완료 |

- **유지한 경계**: AI는 도구를 직접 실행하지 않고 요청만 합니다. 자유 텍스트에 사용자가 제공하지 않은 숫자가 섞이면 문장을 폐기합니다. 조사 한도(2단계·도구 6회·단계 5초·총예산 25초)는 백엔드가 강제하며 AI의 자기 신고를 믿지 않습니다.
- **실측**: 조사 완주율 80.0% · 턴 거부율 7.1% · 턴 실패율 0.0%
- **관련**: [ai-role-expansion.md](plans/ai-role-expansion.md) · [track-b-shadow-results.md](plans/track-b-shadow-results.md)

## C. 아키텍처 (1개 해결 · 3개 미해결)

ARCHITECTURE.md 0절에 현재와 목표가 이미 구분되어 명시된 항목들입니다.

### C1. 분석이 API 요청 안에서 동기 실행됨 — **해결**

- **문제였던 것**: AI 연결 시 요청이 11초 이상 점유됨. 사용자 대기가 곧 AI 예산의 상한이 되어 조사 완주율이 60%에 머무름
- **해결**: `FLOWGUARD_ANALYSIS_ASYNC`(기본 `on`)로 분석을 요청 밖에서 실행하고 202로 즉시 반환. 화면은 대시보드 `refresh_status`를 폴링
- **실측**: 사용자 응답 시간 11,000~13,700ms → **14~17ms**, 조사 완주율 60% → **80%**, 턴 실패율 13.3% → **0%**
- **남은 것**: 프로세스 내 백그라운드 실행이므로 다중 인스턴스 환경에서는 C2가 선행되어야 함
- **관련**: [track-b-shadow-results.md](plans/track-b-shadow-results.md)

### C2. 큐·워커가 없음

- **근거**: `celery`·`redis`·`rq` 의존성 없음
- **현재**: C1이 프로세스 내 백그라운드 실행으로 해소되어 단일 인스턴스에서는 문제없음. 다중 인스턴스 확장 시 필요
- **규모**: 2~3일

### C3. AI 서비스 멱등성이 프로세스 메모리에 있음

- **근거**: `ai_service.py`의 `response_cache`가 512개 상한 dict
- **문제**: AI 서비스를 2대 이상으로 늘리면 "같은 `idempotencyKey`는 한 번만 실행" 보장이 깨짐
- **상태**: ARCHITECTURE.md 0절에 "단일 worker → 목표는 다중 worker"로 명시됨
- **조치**: 공유 저장소 기반 멱등성으로 전환
- **규모**: 1~2일

### C4. 정기 분석이 없음

- **근거**: 스케줄러 코드 없음. README 10장의 "하루 한 번 정기 분석" 미구현
- **조치**: C1·C2 이후 스케줄러 추가
- **규모**: 1일

## 해결 완료 기록

### A. 화면에 즉시 드러나는 문제 — 7개 전부 해결

| 항목 | 이전 | 현재 | 커밋 |
|---|---|---|---|
| A1 샘플 시나리오 | 거래처 1곳, 부족 없음 | 거래처 3곳, 최악 시나리오 안전여유 **-250,000원** | `7606f05` `caff94c` |
| A2 `status` 필드 | 없음 → 전부 "상태 정보 없음" | `daily_positions`에 포함, 화면 표시 정상 | `7606f05` |
| A3 부족금액 범위 | `250,000~250,000` | `50,000~250,000` | `7606f05` |
| A4 "0원 미만" 범례 | 발동 불가 | `safety_margin` 등 안전여유 지표 4종 신설로 근본 해결 | `caff94c` |
| A5 신뢰도 | 10% · "신뢰도 낮음" | **50%** · "예정 수입을 확인할수록 분석이 정밀해져요" | `7606f05` |
| A6 추천 근거 | "API 응답에 추천 근거가 포함되지 않았습니다" | 실제 근거 문장 표시 | `7606f05` |
| A7 위험 근거 카드 | "설명 정보 없음" | 이벤트별 설명 표시 | `7606f05` |

**경보 피로 해소** (`caff94c`) — 실측 검증:
```
이전: STABLE  0일 · VERIFY 32일 · ACT_NOW 59일
현재: STABLE 76일 · VERIFY 13일 · ACT_NOW  2일
ACT_NOW는 8/25~26만 유지, 8/27 확정 입금 후 VERIFY로 해제
```
주차별 원인도 연결됨(금융 이벤트가 있는 5개 주차). README 4장 "평소에는 조용히, 필요할 때만 개입한다"가 실제로 지켜지게 됨.

### B. 운영 기반 — 4개 해결

- **B1 로깅** — 구조화 JSON 로깅 도입. `request_id` 상관관계 추적 포함. 실측 확인
- **B2 CI** — `.github/workflows/ci.yml`. `make check` + Playwright E2E + 진단 아티팩트 업로드
